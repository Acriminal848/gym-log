# Gym Log — สมุดจดเวทบน iPhone (ช่วงที่ 1: จดได้จริง)

แอปเว็บแบบ HTML/CSS/JavaScript ล้วน ไม่มีขั้นตอน build ไม่มี server ไม่มี login
ข้อมูลทั้งหมดเก็บในเครื่อง (IndexedDB) ใช้ offline ได้หลังเปิดแอปครั้งแรกจนโหลดเสร็จ

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | โครงหน้าจอ |
| `styles.css` | หน้าตาบนมือถือ |
| `app.js` | การใช้งานและเชื่อมหน้าจอกับข้อมูล |
| `storage.js` | IndexedDB, สำรอง (export), กู้คืน (import) |
| `progression.js` | การคำนวณ (ช่วงที่ 1: หาผลครั้งก่อน/เป้าหมายตั้งต้น) |
| `manifest.webmanifest` | ชื่อแอปและการเปิดจาก Home Screen |
| `sw.js` | offline cache และการอัปเดต |
| `icons/` | ไอคอนแอป |

## 1) ลองเปิดบนคอมพิวเตอร์ก่อน (ไม่บังคับ)

ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ ห้ามดับเบิลคลิก `index.html` ตรง ๆ (service worker ไม่ทำงานแบบ `file://`)

1. เปิด Terminal ในโฟลเดอร์นี้
2. พิมพ์ `python3 -m http.server 8000`
3. เปิดเบราว์เซอร์ไปที่ `http://localhost:8000/`
4. ผลที่ควรเห็น: หน้า “Gym Log” มีปุ่ม “เริ่ม: Push (ตัวอย่าง)” และ “เริ่ม: Pull (ตัวอย่าง)”

## 2) นำขึ้น GitHub Pages

ต้องมีบัญชี GitHub (ฟรี) และ repository แบบ Public (GitHub Pages ฟรีใช้กับ repo สาธารณะ)

1. เข้า github.com → ปุ่ม **New** → ตั้งชื่อ repository เช่น `gym-log` → เลือก **Public** → **Create repository**
2. ในหน้า repository ว่าง กด **uploading an existing file**
3. ลากไฟล์ **ในโฟลเดอร์นี้** ทั้งหมดขึ้นไป (`index.html`, `styles.css`, `app.js`, `storage.js`, `progression.js`, `manifest.webmanifest`, `sw.js`, โฟลเดอร์ `icons`) แล้วกด **Commit changes**
   - ไฟล์ต้องอยู่ที่ราก repository (ไม่ใช่ซ้อนในโฟลเดอร์อีกชั้น)
   - ไม่ต้องอัปโหลดโฟลเดอร์ `tests` และไฟล์ `README.md` ก็ได้
4. ไปที่ **Settings** → **Pages** → ที่ **Build and deployment** เลือก Source = **Deploy from a branch** → Branch = **main** และโฟลเดอร์ **/ (root)** → **Save**
5. รอประมาณ 1–2 นาที รีเฟรชหน้า Pages จะมีข้อความ “Your site is live at …”
6. ที่อยู่แอปจะเป็น `https://USERNAME.github.io/gym-log/` (ต้องมี `/` ท้ายชื่อ)

แอปใช้พาธแบบ relative ทั้งหมด จึงทำงานใน `/gym-log/` ได้โดยไม่ต้องแก้โค้ด

**ความเป็นส่วนตัว:** GitHub Pages ได้รับเฉพาะไฟล์แอป ประวัติ workout อยู่ในเครื่องของคุณและไม่ถูกอัปโหลด
ห้ามเอาไฟล์สำรอง `gymlog-backup-*.json` ไปไว้ใน repository

## 3) Add to Home Screen บน iPhone

ต้องใช้ **Safari** (ไม่ใช่ Chrome)

1. เปิด `https://USERNAME.github.io/gym-log/` ใน Safari **ตอนมีอินเทอร์เน็ต**
2. รอให้หน้าโหลดเสร็จแล้วเห็นปุ่ม “เริ่ม: Push (ตัวอย่าง)” (นี่คือการโหลดครั้งแรกเพื่อเก็บไฟล์ไว้ใช้ offline)
3. แตะปุ่ม **แชร์** (สี่เหลี่ยมมีลูกศรชี้ขึ้น) → เลื่อนลงแตะ **Add to Home Screen / เพิ่มไปยังหน้าจอโฮม** → แตะ **Add / เพิ่ม**
4. ผลที่ควรเห็น: ไอคอนดัมเบลสีส้มชื่อ “Gym Log” บนหน้าจอโฮม
5. เปิดแอปจากไอคอนนั้นทุกครั้ง (ไม่ใช่จาก Safari)

**สำคัญ:** ข้อมูลที่จดผ่าน Safari ธรรมดากับที่จดผ่านไอคอน Home Screen เป็นคนละที่กัน ให้เลือกใช้ผ่านไอคอนอย่างเดียวตั้งแต่เริ่มจดจริง

## 4) เส้นทางทดลองใช้ (ทำตามทีละข้อ)

1. เปิดแอป → แตะ **เริ่ม: Push (ตัวอย่าง)** → ผลที่ควรเห็น: การ์ด 4 ท่า แต่ละท่าเขียนว่า “ยังไม่เคยเล่นท่านี้”
2. ที่การ์ด Barbell Bench Press ช่อง **kg** พิมพ์ `40` ช่อง **reps** พิมพ์ `10` → แตะ **✓ ยืนยันเซต** → ผลที่ควรเห็น: เซต 1 ขึ้นเครื่องหมายถูกสีเขียวและมีแถบ “ยกเลิก (Undo)” ชั่วคราว
3. ปิดแอป (ปัดทิ้งจาก app switcher) แล้วเปิดใหม่ → ผลที่ควรเห็น: กลับมาที่ workout เดิม เซต 1 ยังอยู่
4. เปิดโหมดเครื่องบิน แล้วปิดแอปและเปิดใหม่ → จดเซต 2 ได้ตามปกติ
5. ที่การ์ด Incline Dumbbell Press แตะ **เปลี่ยนท่า** → เลือก **Chest Press Machine** → ผลที่ควรเห็น: การ์ดเปลี่ยนชื่อและมีป้าย “เปลี่ยนท่าวันนี้” แผน Push ในหน้าหลักไม่เปลี่ยน
6. แตะ **จบ workout** → **จบและเก็บเข้าประวัติ** → ผลที่ควรเห็น: หน้า “ประวัติ” มีรายการวันนี้
7. แตะ **เริ่ม: Push (ตัวอย่าง)** อีกรอบ → ผลที่ควรเห็น: Bench แสดง “ครั้งก่อน 40×10 …” และมีช่องกรอกที่เติมค่าเสนอสีจางให้ (ยังไม่นับจนกดยืนยัน)
8. แท็บ **สำรอง** → **ส่งออกข้อมูล** → เลือก “Save to Files / บันทึกไปที่ไฟล์” → ได้ไฟล์ `gymlog-backup-วันที่.json`
9. แท็บ **สำรอง** → **เลือกไฟล์สำรอง** → เลือกไฟล์เมื่อกี้ → ผลที่ควรเห็น: หน้า “สรุปไฟล์สำรอง” ยังไม่มีอะไรถูกทับจนกว่าจะเลือก “รวมเข้ากับข้อมูลเดิม” หรือ “แทนที่ข้อมูลเดิมทั้งหมด” (แล้วต้องกดยืนยันอีกครั้ง)

ท่าและแผนตัวอย่างไม่ใช่ข้อมูลจริงของคุณ — จะเพิ่ม/แก้ได้ในช่วงที่ 2

## 5) ปล่อยเวอร์ชันใหม่ (เมื่อแก้โค้ดภายหลัง)

1. แก้ไฟล์ที่ต้องการ
2. เปลี่ยน `VERSION` ใน `sw.js` **และ** `APP_VERSION` ใน `app.js` ให้ตรงกัน (เช่น `1.0.1`) ถ้าไม่เปลี่ยน iPhone จะไม่รู้ว่ามีของใหม่
3. อัปโหลดไฟล์ที่แก้ขึ้น GitHub (Commit)
4. บน iPhone เปิดแอป → จะมีแถบสีส้มด้านบน “มีเวอร์ชันใหม่” → แตะ **อัปเดตตอนนี้** เมื่อสะดวก (แอปจะไม่รีโหลดเองกลางการจด และข้อมูลที่บันทึกแล้วไม่หาย) หรือไปแท็บ **สำรอง** → **ตรวจหาเวอร์ชันใหม่**

## ข้อควรรู้

- ข้อมูลไม่ได้สำรองบน cloud อัตโนมัติ — ส่งออกไฟล์สำรองเป็นระยะและเก็บไว้ใน Files/iCloud Drive ของคุณเอง
- ถ้าลบแอปออกจาก Home Screen หรือล้างข้อมูลเว็บของ Safari ข้อมูลในแอปจะหายไปด้วย
- ยังไม่มี sync ข้ามเครื่อง (ตามขอบเขต MVP)
- การอ้างอิง FitnessTrack: **ยังไม่ได้ตรวจ** โค้ดหรือ license ของโปรเจกต์นั้น และไม่มีโค้ดจากโปรเจกต์นั้นอยู่ในแอปนี้ กติกา progression ในช่วงที่ 3 จะเขียนตามหลักการที่กำหนดไว้ และถ้าจะนำโค้ดจริงมาใช้ จะตรวจ license ก่อน

ทดสอบอัตโนมัติแล้วใน Chromium (จำลองหน้าจอ iPhone, เปิดที่พาธ `/app-name/`, ปิดเน็ตจริงด้วย offline mode):
เปิดแอป · จดเซต · Undo · แก้เซต · ข้ามเซต · warm-up ไม่นับ · draft ไม่นับเป็นผลงาน · ปิด/เปิดแล้วเล่นต่อ ·
offline เปิดและจดได้ · เปลี่ยนท่าแล้วประวัติไม่ปนกัน · ครั้งก่อน/เป้าหมายตั้งต้น · Export/Import (merge/replace/ไฟล์เสีย/เวอร์ชันใหม่กว่า) ·
ขึ้นเวอร์ชันใหม่โดยไม่รีโหลดเอง · ประวัติอยู่ครบหลังอัปเดต

**ยังต้องให้คุณลองบน iPhone จริง** (ทดสอบในเครื่องจำลองไม่ได้):
- Add to Home Screen แล้วไอคอน/ชื่อ/เปิดเต็มจอถูกต้อง
- แป้นตัวเลขของ iOS ขึ้นเมื่อแตะช่อง kg และ reps และไม่ซูมหน้าจอเอง
- เปิดโหมดเครื่องบินแล้วเปิดแอปจากไอคอน จดและดูประวัติได้
- ปุ่ม “ส่งออกข้อมูล” เปิดหน้าแชร์ของ iOS และบันทึกลง Files ได้ / การเลือกไฟล์ตอน Import จาก Files
- การวางตำแหน่งปุ่มกับแถบเมนูล่างและ safe area (รอยบากด้านบน/แถบด้านล่าง) ใช้มือเดียวสะดวกหรือไม่
- ข้อมูลยังอยู่หลังปิดแอปทิ้งไว้หลายวัน
