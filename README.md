# Gym Log — สมุดจดเวทบน iPhone (เวอร์ชัน 1.3.1 · หน้าตา Pearl Ledger + โปรแกรม PPL + ไอคอนใหม่)

แอปเว็บแบบ HTML/CSS/JavaScript ล้วน ไม่มีขั้นตอน build ไม่มี server ไม่มี login
ข้อมูลทั้งหมดเก็บในเครื่อง (IndexedDB) ใช้ offline ได้หลังเปิดแอปครั้งแรกจนโหลดเสร็จ

## 1.3.x เปลี่ยนอะไร

- ทำหน้าตาใหม่ทั้งหมดตาม `Workout-PWA-UX-Design-Brief-v0.1` (Pearl Ledger): พื้นขาวมุกเทา ตัวอักษรเข้ม ปุ่มหลักสีถ่าน ฟอนต์ Inter + Noto Sans Thai ฝังในแอป (มี license) ไอคอนเส้นบางชุดเดียว
- **แก้ปัญหาคอนทราสต์**: ชื่อแผน/ชื่อท่า/ชิปที่เลือก ใช้ตัวเข้ม `#192026` บนพื้นสว่าง หรือตัวขาวบนพื้นถ่าน ไม่มีตัวหนังสือบนพื้นไล่เฉดอีกต่อไป (ตรวจจากภาพที่แสดงผลจริง ดู `tests/contrast_audit.py`) สีตัวอักษรรอง `#4F5B65` เข้มกว่า brief เล็กน้อย (`#596671`) เพื่อให้ผ่าน 4.5:1 บนพื้นเฉดม่วง/มิ้นต์
- เมนูล่าง 4 จุด: หน้าแรก / แผน / ท่า / ประวัติ (สำรอง/กู้คืนอยู่บนหน้าแรก พร้อมวันที่สำรองล่าสุด)
- **ดูแผน ≠ เริ่มฝึก**: เปิดแผนดูได้ไม่สร้างอะไร ต้องกด “เริ่มฝึกแผนนี้” จึงเริ่ม session; session ค้างอยู่บนหน้าแรก (“เล่นต่อ” / “จัดการ session”)
- กติกาชีวิต session: ว่างเปล่า → ยกเลิก/แทนที่ได้โดยไม่มีประวัติ · มีเซตจริง → เลือก 3 ทาง (กลับไปเล่น / เก็บผลเดิมแล้วเริ่มใหม่ / ยกเลิกผลเดิม — ต้องยืนยัน บอกจำนวนเซต) · จบโดยไม่มีเซตที่ยืนยัน → ไม่สร้างประวัติ · warm-up นับเป็นข้อมูลก่อนเตือน แต่ไม่นับเป็น working set
- หน้าจดแบบตารางเดียว: วงกลมยืนยัน · เซต · ครั้งก่อน · น้ำหนัก · reps; แตะ ✓ เพื่อแก้; เป้าหมายอยู่เหนือตาราง (เปิดดูเหตุผลได้); ปุ่ม “เซตที่เหลือใช้น้ำหนักนี้” เป็นการกดเอง; ไม่มีปุ่มบันทึกใหญ่; Undo ค้างจนกว่าจะทำอย่างอื่น
- “ท่าทางเลือก” (เฉพาะวันนี้ ใช้ประวัติของท่าที่เลือก) และ “ประวัติท่านี้” ในหน้าจด
- **โปรแกรม PPL ของคุณถูกใส่เป็นแผนพร้อมใช้** (34 ท่า, 4 แผน: Push 6 ท่า/17 เซต · Pull 5/16 · Legs 7/21 · วันเสริม 4/8) พร้อมชื่อท่ามาตรฐานและไอคอนท่าทาง 25 แบบ; ท่าตัวอย่างของ 1.2.0 ถูกเอาออก (ถ้าเคยมีประวัติ จะ “เก็บเข้าคลัง” ไม่ลบ)
- (1.3.1) เปลี่ยนไอคอนแอปเป็นโลโก้แขนกล้าม-G ที่คุณให้มา
- ท่าแต่ละท่าตั้ง “ไอคอนท่าทาง” และ “หมายเหตุสั้น” ได้ในหน้าแก้ไขท่า

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | โครงหน้าจอ |

| `app.js` | การกระทำ: session, จดเซต, Undo, สลับท่า, แผน/ท่า, สำรอง/กู้คืน, อัปเดต |
| `storage.js` | IndexedDB, ตรวจไฟล์สำรอง, export/import |
| `program.js` | โปรแกรม PPL (ท่า/แผน/ท่าทางเลือก) + การย้ายข้อมูลจาก 1.2.0 |
| `icons.js` | ไอคอนท่าทาง 25 แบบ + ไอคอนเมนู |
| `progression.js` · `summary.js` | กติกา double progression · สรุปรายท่า/รายสัปดาห์ |
| `fonts/` | Inter, Noto Sans Thai (woff2) + `LICENSE-*-OFL.txt` |
| `manifest.webmanifest` · `sw.js` · `icons/` | การติดตั้ง · offline cache/อัปเดต · ไอคอนแอป |

## 2) ลองเปิดบนคอมพิวเตอร์ก่อน (ไม่บังคับ)

ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ ห้ามดับเบิลคลิก `index.html` ตรง ๆ

1. เปิด Terminal ในโฟลเดอร์นี้ → `python3 -m http.server 8000`
2. เปิด `http://localhost:8000/` → ผลที่ควรเห็น: หน้า “Gym Log” มีการ์ด PPL · Push / Pull / Legs / วันเสริม

## 3) นำขึ้น GitHub Pages

1. github.com → **New** → ตั้งชื่อ `gym-log` → **Public** → **Create repository**
2. **uploading an existing file** → ลากไฟล์ **และโฟลเดอร์ `fonts` `icons`** ทั้งหมดในโฟลเดอร์นี้ขึ้นไป (ไฟล์ต้องอยู่ที่รากของ repository) → **Commit changes** (ไม่ต้องอัปโหลด `tests` และ `README.md` ก็ได้)
3. **Settings → Pages** → Source = **Deploy from a branch** → Branch = **main** / **(root)** → **Save**
4. รอ 1–2 นาที ที่อยู่แอป: `https://USERNAME.github.io/gym-log/`

แอปใช้พาธ relative ทั้งหมด ทำงานใน `/gym-log/` ได้ไม่ต้องแก้โค้ด
**ความเป็นส่วนตัว:** GitHub ได้รับเฉพาะไฟล์แอป ประวัติ workout อยู่ในเครื่องคุณ ห้ามเอาไฟล์สำรอง `gymlog-backup-*.json` ไปไว้ใน repository

## 4) Add to Home Screen บน iPhone (ใช้ Safari)

1. เปิดลิงก์ใน Safari ตอนมีเน็ต รอจนเห็นหน้าแผน
2. **แชร์** → **Add to Home Screen** → **Add** → ได้ไอคอนรูปแขนกล้าม-G สีกรมท่า
3. เปิดจากไอคอนนั้นทุกครั้ง — ข้อมูลใน Safari ธรรมดากับในไอคอนเป็นคนละที่ ให้ใช้ผ่านไอคอนอย่างเดียว

## 5) เส้นทางทดลองใช้

1. หน้าแรก → แตะ **PPL · Pull** → เห็นรายการท่า (ยังไม่เริ่มฝึก) → **เริ่มฝึกแผนนี้**
2. ช่อง kg พิมพ์ `50` ช่อง reps `12` → แตะ **วงกลมซ้าย** → วงกลมกลายเป็น ✓ มีแถบ **ย้อนกลับ** และปุ่ม **เซตที่เหลือใช้น้ำหนักนี้ (50 kg)**
3. จดครบเซต → **ท่าถัดไป** (ไม่ข้ามเอง)
4. แตะ **ท่าทางเลือก** → ดูรายการ → เลือก (เฉพาะวันนี้) → แผนหลักไม่เปลี่ยน
5. กลับ **หน้าแรก** → มีแถบ session ค้าง → **เล่นต่อ** · ปิด/เปิดแอปใหม่ก็ยังอยู่
6. **จัดการ session → จบ** → ได้ประวัติ; ครั้งถัดไปเป้าหมายมาจากผลจริงครั้งก่อน
7. **หน้าแรก → สำรอง / กู้คืนข้อมูล → ส่งออกข้อมูล** เก็บไฟล์ไว้ใน Files

## 6) กติกา progression (สั้น ๆ)

ใช้ประวัติล่าสุดของ **ท่าเดียวกัน + อุปกรณ์/วิธีนับน้ำหนักเดียวกัน** นับเฉพาะ working set ที่ทำเสร็จ (warm-up และเซตที่ข้ามไม่นับ)

| ครั้งก่อน | แอปเสนอ |
|---|---|
| น้ำหนักเดียว ทุกเซตถึง reps สูงสุด และจดครบตามแผน | เพิ่มน้ำหนัก 1 ขั้น (ตาม step ของท่า) เริ่มที่ reps ต่ำสุดของช่วง |
| น้ำหนักเดียว ยังไม่ถึงสูงสุดทุกเซต | น้ำหนักเดิม เพิ่ม reps = reps ต่ำสุดของครั้งก่อน + 1 (ไม่เกินสูงสุด) |
| มีเซตต่ำกว่า reps ต่ำสุด ครั้งเดียว | น้ำหนักเดิม ลองซ้ำ (ไม่ลดน้ำหนักทันที) |
| ต่ำกว่า reps ต่ำสุดที่น้ำหนักเดิม **ติดกัน 2 ครั้ง** | เสนอลด 1 ขั้น |
| ถึง reps สูงสุดแต่จดไม่ครบตามแผน (เช่นข้ามเซต) | น้ำหนักเดิม ไม่เพิ่มน้ำหนัก และบอกเหตุผล |
| ใช้น้ำหนักหลายค่าในครั้งเดียว | เสนอแบบระมัดระวัง: น้ำหนักที่ทำบ่อยสุด (เท่ากันเลือกที่เบากว่า) ไม่เพิ่มน้ำหนัก และบอกข้อจำกัด |
| เคยเล่นแต่ต่างอุปกรณ์/วิธีนับน้ำหนัก | ไม่เสนอตัวเลข (เทียบกันไม่ได้) ให้กรอกเอง |
| ไม่เคยเล่นท่านี้ | ไม่เสนอ ให้กรอกน้ำหนักเริ่มต้นเอง |

เป็นเพียงคำแนะนำ — แก้น้ำหนัก/reps ได้เองเสมอ และแอปไม่ถือว่าคุณทำตามเป้าโดยอัตโนมัติ

## 7) อัปเกรดจากเวอร์ชันก่อนหน้า (ที่ขึ้น GitHub Pages ไปแล้ว)

โครงข้อมูลยังเป็น v1 เหมือนเดิม ไม่ต้องแปลงไฟล์

1. **ก่อนอัปเกรด** ส่งออกไฟล์สำรองจากแอปเดิมเก็บไว้
2. อัปโหลดไฟล์ทั้งหมดจากโฟลเดอร์นี้ทับของเดิม (**ไฟล์ใหม่:** `core.js` `views.js` `icons.js` `program.js` และโฟลเดอร์ `fonts`) → Commit
3. เปิดแอปจากไอคอนตอนมีเน็ต → แถบ “มีเวอร์ชันใหม่” → **อัปเดตตอนนี้** (หรือเมนู สำรอง → ตรวจหาเวอร์ชันใหม่)
4. ผลที่ควรเห็น: หน้าตาใหม่, แผน PPL 4 แผน, กล่องแจ้ง “เพิ่มโปรแกรม PPL ให้แล้ว” (กด **รับทราบ** ครั้งเดียวหาย), ประวัติเดิมอยู่ครบ, session ที่ค้างอยู่ยังเล่นต่อได้
   - ท่า/แผน “ตัวอย่าง” ที่ไม่เคยใช้ถูกเอาออก; ที่เคยมีประวัติถูกเก็บเข้าคลัง (ประวัติยังอยู่); ท่า/แผนที่คุณสร้างเองไม่ถูกแตะ
   - ถ้ากู้คืนไฟล์สำรอง (replace) แอปจะไม่เติมโปรแกรม PPL ซ้ำ

## 8) ปล่อยเวอร์ชันใหม่ภายหลัง

1. แก้ไฟล์ → เปลี่ยน `VERSION` ใน `sw.js` **และ** `GL.APP_VERSION` ใน **`core.js`** ให้ตรงกัน
2. ไฟล์ใหม่ต้องเพิ่มใน `ASSETS` ของ `sw.js` ด้วย (ไม่งั้นจะไม่ถูกแคชสำหรับ offline)
3. อัปโหลดขึ้น GitHub → บน iPhone แตะ **อัปเดตตอนนี้** ในแถบที่ขึ้น (แอปไม่รีโหลดเองกลางการจด)

## ข้อควรรู้

- ข้อมูลไม่ได้สำรองบน cloud อัตโนมัติ — ส่งออกไฟล์สำรองเป็นระยะ เก็บใน Files/iCloud Drive
- ลบแอปออกจาก Home Screen หรือล้างข้อมูลเว็บของ Safari = ข้อมูลหาย
- ยังไม่มี sync ข้ามเครื่อง
- ท่าทำทีละข้าง (Single-Arm): 1 เซตในตาราง = ครบทั้งสองข้าง จดน้ำหนัก/reps เป็นค่าต่อข้าง
- ช่วง reps ตั้งต่อท่า (ไม่ใช่ต่อแผน) แก้ได้ในหน้า “ท่า”
- ตัวเลขที่เสนอเป็นกติกาง่าย ๆ ที่อธิบายได้ ไม่ใช่การรับประกันผล
- การอ้างอิง FitnessTrack (https://github.com/Gman0909/FitnessTrack): ตรวจ license แล้วเป็น **MIT** (Copyright (c) 2026 Giuliano Maciocci) และได้อ่านไฟล์ `shared/algorithm.js` (ไม่ได้อ่านทั้งโปรเจกต์) กติกาในแอปนี้ **เขียนใหม่เองทั้งหมด ไม่ได้คัดลอกโค้ด** เพราะวิธีของเขาต่างกัน (แยกเป้าต่อเซต และเทียบด้วย volume) รับแนวคิดมา 2 ข้อ คือ ลดน้ำหนักเมื่อพลาดขั้นต่ำติดกัน 2 ครั้ง และเซตที่ข้ามไม่ถือเป็นความล้มเหลว (ให้เครดิตไว้ที่หัวไฟล์ `progression.js` แล้ว) ไม่ได้นำ backend หรือระบบสมาชิกของโปรเจกต์นั้นมาใช้

## สถานะการทดสอบ

รันอัตโนมัติใน Chromium (จำลองหน้าจอ iPhone 390×844, 375×667, 430×932, offline จริง) สคริปต์ใน `tests/` (ต้องมี Python + Playwright + Pillow):

- `node tests/unit.test.js` — 40 รายการ: กติกา progression/สรุป · โปรแกรม PPL (จำนวนท่า/เซต/ท่าทางเลือก/ไอคอนถูกต้อง, ติดตั้งซ้ำไม่ซ้ำ, ย้ายข้อมูลไม่ทับของผู้ใช้)
- `python3 tests/e2e_v13.py http://localhost:8000/` — 141 รายการ: เครื่องใหม่ · ดูแผนไม่สร้าง session · ชีวิต session (แทนที่ session ว่าง, 3 ทางเลือก, ยืนยันก่อนทิ้ง, จบโดยไม่มีเซต) · ตารางจด/Enter ไม่ยืนยัน/กดซ้ำเร็ว/Undo/เซตที่เหลือใช้น้ำหนักนี้/ท่าถัดไป · warm-up · ข้ามเซต · ท่าทางเลือก (ก่อน/หลังมีเซต) · ประวัติท่านี้และเป้าหมาย · แก้แผน/ท่า · บันทึกล้มเหลว · สำรอง/กู้คืน (ไฟล์เสีย, เวอร์ชันใหม่กว่า, replace/merge, ข้อมูลเหมือนเดิมทุกไบต์) · เลย์เอาต์ (ปุ่ม ≥44px, ช่องกรอก ≥16px, ไม่เลื่อนแนวนอน) · offline
- `python3 tests/contrast_audit.py http://localhost:8000/` — วัดคอนทราสต์ WCAG จากพิกเซลพื้นหลังที่แสดงผลจริง 24 หน้าจอ/แผ่น (~470 ข้อความ) ผ่านเกณฑ์ 4.5:1 ทั้งหมด (ค่าต่ำสุด ≈ 4.58 คือ placeholder ของช่องกรอก)
- `python3 tests/upgrade_from_v12.py <โฟลเดอร์ 1.2.0> <โฟลเดอร์ 1.3.0>` — 17 รายการ: อัปเกรดบนข้อมูล 1.2.0 (ประวัติครบ, ท่าตัวอย่างที่มีประวัติถูกเก็บเข้าคลัง, ท่า/แผนผู้ใช้ไม่ถูกแตะ, session ค้างจาก 1.2.0 เล่นต่อได้)
