## 1.6 เปลี่ยนอะไร (มีการย้ายข้อมูลเล็กน้อย — แบบไม่ทำลาย)

- **แยกชื่อกล้ามเนื้อ**: “ไหล่” → **ไหล่ข้าง / ไหล่หลัง**, “ขา” → **ต้นขาหน้า / ต้นขาหลัง** (Leg Press/Hack Squat/Leg Extension = ต้นขาหน้า · Leg Curl = ต้นขาหลัง · Lateral Raise = ไหล่ข้าง · Reverse Pec Deck/Rear Delt Fly = ไหล่หลัง) ทำให้ดูรอบสัปดาห์ได้ละเอียดขึ้น
  - **การย้ายข้อมูลปลอดภัย**: แก้เฉพาะ “ท่าที่โปรแกรม PPL ติดตั้งให้” (รหัส `ppl-*`) ที่ชื่อกล้ามเนื้อยังเป็นค่าเดิม — ท่าที่คุณสร้างเอง หรือท่า PPL ที่คุณแก้ชื่อกล้ามเนื้อเองแล้ว **ไม่ถูกแตะ** · ประวัติการฝึก (workouts) ไม่ถูกแตะเลย (ในประวัติไม่ได้เก็บชื่อกล้ามเนื้อ ระบบดูจากท่าปัจจุบัน) · ก่อนแก้จะเก็บค่าเดิมไว้ที่ settings คีย์ `muscleSplitBackup` (รายการ `{id, muscle}`) · ทำใน transaction เดียว (ล้มเหลว = ไม่เปลี่ยนอะไร) · ทำครั้งเดียว (ธง `muscleSplit`) และรันซ้ำหลังกู้คืนไฟล์สำรองเก่า
  - ท่าที่คุณสร้างเองและใช้ชื่อ “ไหล่”/“ขา” ยังแสดงเป็นกลุ่มของมันเอง แก้ได้ในหน้าแก้ไขท่า
- **ประวัติแบ่งเป็น ภาพรวม / รายท่า / รายครั้ง** (ภาพรวมเป็นหน้าแรกของแท็บ):
  - **ภาพรวม**: เซตต่อกล้ามเนื้อรายสัปดาห์ (เลื่อนดูย้อนหลังได้) พร้อมจำนวนครั้งที่ฝึกต่อกล้ามเนื้อ — นับ **เซตตรง** = เซต working ที่ทำเสร็จ ตามกล้ามเนื้อหลักของท่านั้น (ไม่นับผลทางอ้อม, warm-up/เซตที่ข้ามไม่นับ; ไม่คิดจาก kg×reps) · เส้นอ้างอิง 10/20 เซตต่อสัปดาห์ **ปิดไว้เป็นค่าเริ่มต้น** เปิดได้ที่ตั้งค่า (ไม่มีสีแดง/ไม่ตำหนิ) · **ตารางความสม่ำเสมอ 12 สัปดาห์** (แถว = จ–อา, คอลัมน์ = สัปดาห์ เก่า→ใหม่, มีตัวเลขจำนวนครั้งในช่อง ไม่ใช้สีอย่างเดียว) พร้อมรวม/เฉลี่ยต่อสัปดาห์
  - **รายท่า → เปิดท่า**: การ์ดตัวเลข (ล่าสุด/ดีที่สุด/จำนวนครั้ง) · **กราฟเส้นแนวโน้ม** เมื่อเล่นท่านั้น ≥ 4 ครั้ง (ต่ำกว่านั้นแสดงการ์ดตัวเลขและบอกเงื่อนไข) สลับ “น้ำหนักสูงสุด” / “1RM โดยประมาณ (Epley)” · จุดสถิติใหม่ **◆ PR** (ใช้รูปเพชร + ตัวอักษร ไม่พึ่งสี; ครั้งแรกที่เล่นไม่นับเป็น PR; เทียบเฉพาะท่า+อุปกรณ์+วิธีนับน้ำหนักเดียวกัน) · รายการตัวเลขรายครั้งใต้กราฟ มีป้าย PR
  - **สรุปหลังจบ session**: ระยะเวลา · จำนวนเซต · จำนวนท่า · สถิติใหม่ (PR) · กล้ามเนื้อที่ได้เซตวันนี้
  - หน้าประวัติว่าง = มีข้อความและปุ่มเริ่มฝึก (ไม่ใช่ทางตัน)
- ไฟล์ใหม่ `charts.js` (วาดกราฟ SVG เป็นฟังก์ชันล้วน) · ตั้งค่าใหม่ `showTargets` (เก็บ/ส่งออกเฉพาะเมื่อผู้ใช้ตั้ง)
- (เลิกแท็บ “รายสัปดาห์” แบบรายท่าเดิมในหน้าประวัติ — ภาพรวมรายสัปดาห์ใหม่แทนที่; ดูรายสัปดาห์ของแต่ละท่าได้ในหน้าท่า)

## 1.5 เปลี่ยนอะไร (หน้าตาและหน้าแรก — ไม่แตะข้อมูล)

- **สีเน้นสีเดียว = ส้ม** (`--accent #FF8A1F`): ปุ่มหลัก, ตัวเลือกที่เลือกอยู่, วงกลมยืนยันของ “เซตปัจจุบัน”, จุดวันที่ทำแล้ว, สวิตช์ที่เปิด, แถบพักครบเวลา · **ตัวอักษรบนพื้นส้มเป็นสีเข้มเสมอ (คอนทราสต์ ~7:1)** ไม่ใช้ส้มเป็นสีตัวอักษรบนพื้นขาว (ถ้าจำเป็นใช้ส้มเข้ม `#8A4200` ≥ 6:1) · ขอบของพื้นส้มใช้ `#A85500` เพื่อให้เห็นขอบ ≥ 3:1 · เลิกใช้เฉดม่วง/มิ้นต์ พื้นหลังเป็นสีนวลเรียบ
- **หน้าแรกใหม่**:
  - การ์ด **“วันนี้ · แผนถัดไป”** เสนอแผนถัดไปตามวงจร Push → Pull → Legs (ต่อจาก session ที่จบล่าสุดในวงจร; “วันเสริม” ไม่ขยับวงจร) กด **เริ่ม** ได้ทันที หรือ “ดูแผน” · ถ้ามี session ค้าง การ์ดนี้ซ่อนและแสดงแถบ “เล่นต่อ” แทน · ถ้าวันนี้จดไปแล้ว ป้ายเปลี่ยนเป็น “จดไปแล้ว” และปุ่มเริ่มไม่เด่น
  - **แถบสัปดาห์ จ–อา**: ติ๊ก + ชื่อแผนในวันที่จด, วงแหวนที่วันนี้, วันที่ยังไม่ถึงเป็นเส้นประ, ตัวเลข x/3 ครั้ง (นับเฉพาะ session ที่จบและมีเซตจริง) — ไม่มีสีแดง ไม่ตำหนิวันที่ไม่ได้เล่น
  - **ชิป “ยังไม่ได้เล่นสัปดาห์นี้”**: กล้ามเนื้อที่โปรแกรมครอบคลุมแต่ยังไม่มีเซตตรงในสัปดาห์นี้ (แสดงเมื่อสัปดาห์นี้จดแล้ว ≥1 ครั้ง) พร้อมคำอธิบายว่าเป็นตัวช่วยจำ ไม่ใช่เป้า
  - **แผนทั้งหมด** เป็นแถวบรรทัดเดียว (ชื่อ · จำนวนท่า/เซต · ล่าสุด)
  - **สำรองข้อมูล** เหลือบรรทัดเดียว (วันที่ + ปุ่ม) และเตือนสีส้มเมื่อสำรองเกิน 14 วัน หรือมี session ใหม่ ≥5 ครั้งที่ยังไม่สำรอง
- เปลี่ยนเวอร์ชันเป็น 1.5.0 เท่านั้น ไม่มีการแก้โครงข้อมูล (ยืนยันซ้ำด้วย `tests/upgrade_from_prev.py`)

## 1.4 เปลี่ยนอะไร (ไม่แตะข้อมูลเดิม)

- **โหมดโฟกัสตอนจด**: ซ่อนเมนูล่างระหว่างจด (ออกด้วย “หน้าแรก”), หัวหน้าจอกะทัดรัด, ปุ่มรอง (เปลี่ยนท่า/ประวัติ/⋯) ดูเงียบลง, ปุ่ม **ท่าถัดไป / จบ** ติดขอบล่างเมื่อครบเซต, ตัวอักษรเล็กขยายเป็น ≥14px
- **ตัวจับเวลาพัก**: ยืนยันเซตแล้วเริ่มนับเอง (ค่าเริ่มต้น **90 วินาที**) แถบล่างมี ข้าม / −15 / +15 · พักครบมีเสียงสั้น ๆ + ข้อความ และนับเวลาที่เกินต่อ · คำนวณจากเวลาจริง สลับแอป/จอหน่วงแล้วไม่เพี้ยน · อยู่ในหน่วยความจำ ไม่เขียนลงฐานข้อมูล
- **ตั้งค่า** (ไอคอนฟันเฟืองมุมขวาบนหน้าแรก): เปิด/ปิดนับอัตโนมัติ · เวลาพัก 60/90/120/180 หรือกำหนดเอง 10–900 วิ · เสียงเตือน · เปิดจอค้างระหว่างจด (Wake Lock) · และตั้ง **เวลาพักเฉพาะท่า** ได้ในหน้าแก้ไขท่า
- **เพิ่ม/แก้ท่าระหว่างจด ไม่ต้องออกไปที่แท็บอื่น**:
  - สร้างท่าใหม่แบบเร็วในหน้าจดเลย (ชื่อ + กล้ามเนื้อ + อุปกรณ์; ที่เหลือตั้งค่าให้ แก้ละเอียดทีหลังได้) แล้วใช้ท่านั้นทันที — ใช้ได้ทั้งตอน เพิ่มท่า / เปลี่ยนท่า / แก้แผน
  - ท่าที่เพิ่มจะแทรก **ต่อจากท่าที่กำลังดู** และพาไปที่ท่านั้นเลย เลือกจำนวนเซตได้
  - **ลบท่าออกจาก session** ได้ (ถ้ามีเซตที่จดไว้จะเตือนจำนวนก่อน) พร้อมปุ่มย้อนกลับ
  - **จดผิดท่า**: ในหน้า “เปลี่ยนท่า” เลือก “จดผิดท่า · แก้ที่จดไปแล้ว” จะย้ายเซตที่จดไว้ทั้งหมดไปเป็นท่าที่ถูก (น้ำหนัก/reps เดิมคงอยู่) ส่วน “เปลี่ยนเฉพาะเซตที่เหลือ” คือพฤติกรรมเดิม (เซตที่จดแล้วคงไว้ที่ท่าเดิม)
- คำอธิบาย “ตัวเลขสีเทาคือคำแนะนำ” แสดงแค่จนกว่าจะกด “เข้าใจแล้ว”
- Motion สั้น ๆ: ปุ่มยุบเมื่อกด · ติ๊กเด้งเมื่อยืนยันเซต · แผ่นเลื่อนขึ้น · แถบย้อนกลับเลื่อนเข้า (ปิดอัตโนมัติถ้าเครื่องตั้ง “ลดการเคลื่อนไหว”)
- แก้บั๊ก: หน้าจอเลื่อนเองหลังแตะช่องกรอก ทำให้ปุ่มวงกลมยืนยัน “หลุดจากนิ้ว” ถ้ากดเร็ว ๆ — ตอนนี้เลื่อนเฉพาะเมื่อช่องถูกบัง
- **ความปลอดภัยของข้อมูล**: ชื่อ/เวอร์ชัน/store ของฐานข้อมูลเหมือนเดิม (`gymlog` v1) ฟิลด์ใหม่เป็นแบบ “เพิ่ม” เท่านั้น (`restSec` ในท่า, คีย์ตั้งค่า `restSeconds` `restAuto` `restSound` `keepAwake` `hintSug`) ไม่มีการแปลงหรือลบข้อมูลเดิม และไฟล์สำรองจากแอปเก่าที่ไม่มีฟิลด์เหล่านี้ export ออกมาเหมือนเดิมทุกตัวอักษร (พิสูจน์ด้วย `tests/upgrade_from_prev.py`)

## 2) ลองเปิดบนคอมพิวเตอร์ก่อน (ไม่บังคับ)

## 5) เส้นทางทดลองใช้

1. หน้าแรก → แตะ **PPL · Pull** → เห็นรายการท่า (ยังไม่เริ่มฝึก) → **เริ่มฝึกแผนนี้**
2. ช่อง kg พิมพ์ `50` ช่อง reps `12` → แตะ **วงกลมซ้าย** → วงกลมกลายเป็น ✓ มีแถบ **ย้อนกลับ** และปุ่ม **เซตที่เหลือใช้น้ำหนักนี้ (50 kg)**
3. จดครบเซต → **ท่าถัดไป** (ไม่ข้ามเอง)
4. แตะ **ท่าทางเลือก** → ดูรายการ → เลือก (เฉพาะวันนี้) → แผนหลักไม่เปลี่ยน
5. กลับ **หน้าแรก** → มีแถบ session ค้าง → **เล่นต่อ** · ปิด/เปิดแอปใหม่ก็ยังอยู่
6. **จัดการ session → จบ** → ได้ประวัติ; ครั้งถัดไปเป้าหมายมาจากผลจริงครั้งก่อน
7. **หน้าแรก → สำรอง / กู้คืนข้อมูล → ส่งออกข้อมูล** เก็บไฟล์ไว้ใน Files

## 6) กติกา progression (สั้น ๆ)

ใช้ประวัติล่าสุดของ **ท่าเดียวกัน + อุปกรณ์/วิธีนับน้ำหนักเดียวกัน** นับเฉพาะ working set ที่ทำเสร็จ (warm-up และเซตที่ข้ามไม่นับ)

| ครั้งก่อน | แอปเสนอ |
|---|---|
| น้ำหนักเดียว ทุกเซตถึง reps สูงสุด และจดครบตามแผน | เพิ่มน้ำหนัก 1 ขั้น (ตาม step ของท่า) เริ่มที่ reps ต่ำสุดของช่วง |
| น้ำหนักเดียว ยังไม่ถึงสูงสุดทุกเซต | น้ำหนักเดิม เพิ่ม reps = reps ต่ำสุดของครั้งก่อน + 1 (ไม่เกินสูงสุด) |
| มีเซตต่ำกว่า reps ต่ำสุด ครั้งเดียว | น้ำหนักเดิม ลองซ้ำ (ไม่ลดน้ำหนักทันที) |
| ต่ำกว่า reps ต่ำสุดที่น้ำหนักเดิม **ติดกัน 2 ครั้ง** | เสนอลด 1 ขั้น |
| ถึง reps สูงสุดแต่จดไม่ครบตามแผน (เช่นข้ามเซต) | น้ำหนักเดิม ไม่เพิ่มน้ำหนัก และบอกเหตุผล |
| ใช้น้ำหนักหลายค่าในครั้งเดียว | เสนอแบบระมัดระวัง: น้ำหนักที่ทำบ่อยสุด (เท่ากันเลือกที่เบากว่า) ไม่เพิ่มน้ำหนัก และบอกข้อจำกัด |
| เคยเล่นแต่ต่างอุปกรณ์/วิธีนับน้ำหนัก | ไม่เสนอตัวเลข (เทียบกันไม่ได้) ให้กรอกเอง |
| ไม่เคยเล่นท่านี้ | ไม่เสนอ ให้กรอกน้ำหนักเริ่มต้นเอง |

เป็นเพียงคำแนะนำ — แก้น้ำหนัก/reps ได้เองเสมอ และแอปไม่ถือว่าคุณทำตามเป้าโดยอัตโนมัติ

## 7) อัปเกรดจากเวอร์ชันก่อนหน้า (ที่ขึ้น GitHub Pages ไปแล้ว)

โครงข้อมูลยังเป็น v1 เหมือนเดิม ไม่ต้องแปลงไฟล์

1. **ก่อนอัปเกรด** ส่งออกไฟล์สำรองจากแอปเดิมเก็บไว้
2. อัปโหลดไฟล์ทั้งหมดจากโฟลเดอร์นี้ทับของเดิม (**ไฟล์ใหม่ใน 1.4–1.6:** `rest.js` `charts.js`; ถ้าอัปจาก 1.2.x ต้องมี `core.js` `views.js` `icons.js` `program.js` และโฟลเดอร์ `fonts` ด้วย) → Commit
3. เปิดแอปจากไอคอนตอนมีเน็ต → แถบ “มีเวอร์ชันใหม่” → **อัปเดตตอนนี้** (หรือเมนู สำรอง → ตรวจหาเวอร์ชันใหม่)
4. ผลที่ควรเห็น: หน้าตาใหม่, แผน PPL 4 แผน, กล่องแจ้ง “เพิ่มโปรแกรม PPL ให้แล้ว” (กด **รับทราบ** ครั้งเดียวหาย), ประวัติเดิมอยู่ครบ, session ที่ค้างอยู่ยังเล่นต่อได้
   - ท่า/แผน “ตัวอย่าง” ที่ไม่เคยใช้ถูกเอาออก; ที่เคยมีประวัติถูกเก็บเข้าคลัง (ประวัติยังอยู่); ท่า/แผนที่คุณสร้างเองไม่ถูกแตะ
   - ถ้ากู้คืนไฟล์สำรอง (replace) แอปจะไม่เติมโปรแกรม PPL ซ้ำ

## 8) ปล่อยเวอร์ชันใหม่ภายหลัง

1. แก้ไฟล์ → เปลี่ยน `VERSION` ใน `sw.js` **และ** `GL.APP_VERSION` ใน **`core.js`** ให้ตรงกัน
2. ไฟล์ใหม่ต้องเพิ่มใน `ASSETS` ของ `sw.js` ด้วย (ไม่งั้นจะไม่ถูกแคชสำหรับ offline)
3. อัปโหลดขึ้น GitHub → บน iPhone แตะ **อัปเดตตอนนี้** ในแถบที่ขึ้น (แอปไม่รีโหลดเองกลางการจด)

## ข้อควรรู้

- ข้อมูลไม่ได้สำรองบน cloud อัตโนมัติ — ส่งออกไฟล์สำรองเป็นระยะ เก็บใน Files/iCloud Drive
- ลบแอปออกจาก Home Screen หรือล้างข้อมูลเว็บของ Safari = ข้อมูลหาย
- ยังไม่มี sync ข้ามเครื่อง
- ท่าทำทีละข้าง (Single-Arm): 1 เซตในตาราง = ครบทั้งสองข้าง จดน้ำหนัก/reps เป็นค่าต่อข้าง
- ช่วง reps ตั้งต่อท่า (ไม่ใช่ต่อแผน) แก้ได้ในหน้า “ท่า”
- ตัวเลขที่เสนอเป็นกติกาง่าย ๆ ที่อธิบายได้ ไม่ใช่การรับประกันผล
- การอ้างอิง FitnessTrack (https://github.com/Gman0909/FitnessTrack): ตรวจ license แล้วเป็น **MIT** (Copyright (c) 2026 Giuliano Maciocci) และได้อ่านไฟล์ `shared/algorithm.js` (ไม่ได้อ่านทั้งโปรเจกต์) กติกาในแอปนี้ **เขียนใหม่เองทั้งหมด ไม่ได้คัดลอกโค้ด** เพราะวิธีของเขาต่างกัน (แยกเป้าต่อเซต และเทียบด้วย volume) รับแนวคิดมา 2 ข้อ คือ ลดน้ำหนักเมื่อพลาดขั้นต่ำติดกัน 2 ครั้ง และเซตที่ข้ามไม่ถือเป็นความล้มเหลว (ให้เครดิตไว้ที่หัวไฟล์ `progression.js` แล้ว) ไม่ได้นำ backend หรือระบบสมาชิกของโปรเจกต์นั้นมาใช้
